# План: Telegram-бот приёма и очистки текста (Next.js + TypeScript)

> Документ — ТЗ для агента-исполнителя. Читать целиком до начала работы. Всё, что помечено **[ОТКРЫТО]**, не решено: агент не выбирает сам, а реализует расширяемо и фиксирует вопрос в отчёте о работе.

## 1. Зачем

Бот — прослойка перед основной системой. Пользователь отдаёт сырой материал (голос, текст, файлы), бот приводит его к чистому виду, который безопасно нарезать на чанки позже. Бот **не режет на чанки** в этой итерации.

Бот делает три вещи:

1. **Принимает** материал: голосовые, аудиофайлы, текст сообщениями, файлы (pdf, md, txt, docx).
2. **Переводит в текст**: речь → Whisper (русский), файлы → извлечение текстового слоя.
3. **Чистит и валидирует**: убирает мусор (разметка, отступы, паразиты речи, обрезки слов, склейки), затем отдельный валидатор доказывает, что текст чистый, и при необходимости чинит.

Сценарий использования: пользователь вызывает `/StartProcess`, шлёт несколько материалов подряд, после каждого бот спрашивает «ещё будут файлы или загружать в систему?» (инлайн-кнопки), по кнопке «Загрузить» всё обрабатывается и пользователь получает результат.

### Ограничения контекста

- Пользователь один (личный бот). Подписчиков, рассылок нет. Whitelist по Telegram ID всё равно обязателен (защита от посторонних, которые найдут бота).
- Язык материала и интерфейса бота — **русский**.
- Бот — прослойка: **ничего не хранит**. Ни файлов на диске, ни БД, ни логов с содержимым. Всё в памяти процесса; временные файлы (если нужны, например для Whisper) удаляются сразу после использования.
- Веб-интерфейса нет. Next.js используется только как сервер для webhook-маршрута.

## 6. Работа бота

### 6.1. Команды

|Команда|Поведение|
|---|---|
|`/start`, `/help`|Короткая справка на русском: как пользоваться, поддерживаемые форматы, лимиты|
|`/StartProcess`|Открывает сессию. Ответ: «Присылай материал: голос, аудио, текст или файлы (pdf, md, txt, docx)». Если сессия уже открыта, предложить продолжить или `/cancel`|
|`/done`|Эквивалент кнопки «Загрузить в систему»|
|`/cancel`|Сбрасывает сессию (с подтверждением, если в ней уже есть материал)|
|`/status`|Показывает, что накоплено в сессии: количество элементов, суммарно символов/минут|

Регистр команды: Telegram принимает `/StartProcess`, но по правилам лучше нижний регистр. Зарегистрировать **оба** варианта: `startprocess` и `StartProcess` (grammY: `bot.command(["StartProcess","startprocess"], …)`); в меню команд (`setMyCommands`) выставить `startprocess`.

### 6.2. Сессия и инлайн-кнопки

- После **каждого** принятого материала бот отправляет сообщение: «Принято: <что именно, кратко>. Ещё будут материалы?» с кнопками **[Ещё добавлю]** и **[Загрузить в систему]** (+ опционально **[Отмена]**).
- Нажатие **[Ещё добавлю]**: бот пишет «Жду следующий материал» и ничего не делает.
- Нажатие **[Загрузить в систему]**: запускается финализация (раздел 7).
- Старое сообщение с кнопками после нажатия редактируется (кнопки убираются), чтобы не нажать дважды.
- Сессия живёт в памяти: `Session { chatId, status, items[], createdAt, lastActivityAt }`. TTL неактивной сессии — 2 часа, затем молча сбрасывается (задать в config).
- Материал без открытой сессии: бот отвечает «Сначала вызови /StartProcess» и ничего не принимает.

### 6.3. Приём материала

Каждый материал сразу превращается в **сырой текст** и кладётся в сессию как `SessionItem { id, kind, label, rawText, meta }`. Преобразование выполняется **при получении**, а не при финализации. Благодаря этому ошибки (слишком длинное аудио, битый файл) видны сразу, и ничего не теряется.

|Вход|Обработка|
|---|---|
|Текст сообщением|Подряд идущие текстовые сообщения склеиваются в один элемент (Telegram режет длинное на куски по 4096). Окно склейки ~1.5 с с debounce, кнопки показываются после окна|
|Файл `.pdf`|`parser/pdf` → текстовый слой. Пустой результат (скан) → ошибка «в PDF нет текстового слоя, сканы не поддерживаются»|
|Файл `.docx`|`parser/docx` (mammoth, raw text)|
|Файл `.md`, `.txt`|UTF-8; при невалидной кодировке (замена `U+FFFD`) попробовать `windows-1251`, иначе ошибка|
|Подпись к файлу (caption)|Если есть — отдельный текстовый элемент **перед** файлом|
|Голосовое (`voice`)|Скачать → Whisper → текст|
|Аудиофайл (`audio` или документ с аудио-mime: mp3, m4a, ogg, wav)|То же|
|Кружки (`video_note`), видео|**Не поддерживаются**, бот отвечает «Кружки не обрабатываю, пришли голосовое или аудиофайл»|
|Пересланные сообщения|Обрабатываются как обычные, без различий|
|Другое (`.doc`, `.rtf`, `.html`, изображения и пр.)|Ответ: формат не поддерживается + список поддерживаемых|

### 6.4. Лимиты

- Размер файла: 20 МБ (лимит Bot API на скачивание). Пользователь считает, что хватает; всё равно проверять `file_size` до скачивания и отвечать понятной ошибкой.
- **Длительность аудио ≤ 50 минут** (`MAX_AUDIO_MINUTES`, по умолчанию 50). Длительность берётся из метаданных Telegram (`voice.duration`, `audio.duration`) **до** скачивания.
    - Если превышено: файл **не отбрасывается молча и не стирается из чата** (он остаётся в переписке, ничего не удаляется), бот не ставит его в обработку и пишет: «Запись длиннее 50 минут (N мин). Раздели её на две части и отправь снова». В сессию такой элемент не добавляется, остальной материал сессии не страдает.
- Размер для Whisper API 25 МБ: при файле ≤ 20 МБ превышения нет. Агент всё равно проверяет и отдаёт понятную ошибку, а не падение.

## 7. Финализация («Загрузить в систему»)

1. Проверить, что в сессии есть элементы; иначе «Нечего загружать».
2. Пометить сессию `processing`, отправить «Обрабатываю…».
3. Для каждого элемента по порядку: `runCleanup` → `autofix(validate)`.
4. Собрать итог:
    - Элементы склеиваются в **один** текст, разделитель — одна пустая строка между элементами (никакой разметки в текст не добавляется).
    - Итоговый текст ещё раз проходит `validate` целиком (склейка могла внести дефекты на стыках).
5. Передать в `OutputSink`.
6. Очистить сессию из памяти. Сырой текст нигде не сохраняется.

**Выдача результата на этой итерации (`TelegramSink`):**

- файл `result-<дата-время>.md` с очищенным текстом (сырой текст без заголовков, без форматирования, как просил пользователь, чтобы он мог проверять систему глазами);
- сообщение с отчётом (раздел 10).

**Позже** (не делать сейчас, но интерфейс `OutputSink` оставить): `SystemSink` отправляет данные в основную систему, пользователю возвращается **только отчёт**, файл с текстом не отдаётся. Переключение через конфиг `OUTPUT_MODE=file+report | report-only`; сейчас доступен только `file+report`.

### 7.1. Очередь

- Webhook должен отвечать Telegram быстро (код 200), иначе Telegram будет повторять апдейт. Поэтому в обработчике апдейта: проверить, дедуплицировать по `update_id`, поставить задачу в очередь, вернуть управление.
- Очередь in-memory, конкурентность 1 (один пользователь; предсказуемый порядок). Задачи: «обработать входящий материал» и «финализировать сессию». Если загрузка принята, она должна выполниться до конца (ретраи при временных сбоях сети/API: до 3 раз с паузой).
- Railway запускает долгоживущий процесс (`next start`), а не serverless-функции, поэтому фоновая работа после ответа не обрывается. Если по факту деплоя окажется иначе, агент сообщает об этом, а не обходит молча.
- **Принятое допущение:** перезапуск процесса теряет очередь и сессию (БД нет). Агент не городит персистентность. Бот пишет пользователю при старте новой сессии, что накопленное до рестарта потеряно, только если обнаружит устаревший callback (кнопка от сессии, которой нет): «Сессия устарела, начни заново /StartProcess».

## 8. Очистка текста (ядро)

### 8.1. Принципы (из заметки)

1. **Правила, а не вручную**: каждая правка описана правилом с `id` и категорией, прогон воспроизводим.
2. **Каждое правило считает, сколько раз сработало** (`stats[category][ruleId]`). Нулевое срабатывание ожидаемого правила видно в отчёте.
3. **Валидатор отдельно от очистки**: разные модули, разный код, критерии не импортируют правила.
4. **Чистка детерминированная**: регулярки и словари. **LLM не используется.**
5. **Предохранитель**: если очистка удалила больше `MAX_REMOVED_RATIO` (по умолчанию 40 %) символов исходника, результат всё равно выдаётся, но в отчёте появляется предупреждение «удалено аномально много, проверь». Тихо выбросить половину текста нельзя.
6. Удаляется **только мусор**. Смысловое содержимое не трогаем.

### 8.2. Вход неизвестный, поэтому правила универсальные

Скрипт из заметки был заточен под один документ с известными дефектами (`разделB0`, 15 конкретных SOP). Здесь вход произвольный: правила пишутся как общие классы дефектов, **без** привязки к конкретным словам и структурам BusiVerse.

### 8.3. Реестр правил

Порядок прогона: **механика → артефакты файлов → точечные дефекты → речь**. Затем финальная нормализация пробелов (чтобы удаления на предыдущих шагах не оставили двойных пробелов).

**A. Механика (`mechanical.ts`)** — применяется ко всему.

- Нормализация переводов строк (`\r\n`, `\r` → `\n`), удаление BOM.
- HTML-теги: `<br>`/`<br/>` → перевод строки, остальные теги (`<u>`, `<b>`, `<span …>` и т. п.) удаляются с сохранением содержимого. HTML-сущности (`&nbsp;`, `&amp;`) декодируются.
- Управляющие символы, zero-width (`U+200B`–`U+200D`, `U+2060`, `U+FEFF`), мягкий перенос `U+00AD` — удалить. NBSP → обычный пробел.
- Символ замены `U+FFFD` — удалить (и посчитать, т. к. сигнал о битой кодировке).
- Табы и серии пробелов → один пробел; пробелы в начале/конце строки убрать; «лишние отступы» в начале строк убрать (для сырого текста структура отступами не нужна).
- Серии пустых строк → одна пустая строка (между абзацами).

**B. Артефакты файлов (`file-artifacts.ts`)** — в основном для PDF, но безопасно для любых.

- Строки, состоящие только из номера страницы («12», «- 12 -», «Стр. 12», «12 / 40», «Page 3 of 10»).
- Колонтитулы: короткая строка (≤ 80 символов), повторяющаяся ≥ 3 раз (с нормализованными цифрами) → удалить.
- Переносы слов на конце строки (`сло-\nво` → `слово`): склеивать только если следующая строка начинается со строчной буквы.
- Жёсткие переносы внутри абзаца (PDF режет строки по ширине страницы): одиночный `\n`, после которого идёт строчная буква и перед которым нет конца предложения, → пробел. Включается флагом `JOIN_HARD_WRAPS` (по умолчанию включён только для `.pdf`).
- Оглавления с точками-заполнителями (`Раздел ........ 12`) → удалить точки-заполнители.

**C. Точечные дефекты (`defects.ts`)** — «обрезки слов» и склейки.

- **Склейка кириллицы и латиницы без разделителя** (в заметке 387 случаев, `месяазатем`, `наCAC`): граница кириллица↔латиница внутри «слова» → вставить пробел, кроме допустимых исключений (аббревиатуры вида `iOS-приложение`, `B2B`-сегмент, слова после дефиса, URL, e-mail, имена файлов, код в бэктиках).
- **Гомоглифы**: слово преимущественно кириллическое, но содержит латинскую букву-двойник (`a, e, o, p, c, x, y`) → заменить на кириллическую. Слово преимущественно латинское с кириллическим двойником → заменить на латинскую.
- **Обрезки слов**: оборванный фрагмент в конце (`пробле- проблема`, `мы по- посмотрим`, `ра- работает`) — удалить обрывок, если за ним следует полное слово с тем же началом. Фрагменты вида `сл-`, висящие в конце фразы без продолжения, → удалить.
- **Заикание/повтор слога**: `по-по-посмотрим` → `посмотрим`; повторы фрагмента через дефис схлопываются.
- **Подряд повторённые слова** (`это это`, `мы мы`): оставить одно. Исключения: допустимые удвоения (`очень очень`, `давно давно`, `бить бить`?) — список исключений в конфиге правил, по умолчанию пустой, кроме `очень`.
- **Висячие предлоги/союзы** в конце строки или перед пустой строкой (в заметке «0 висячих предлогов»): `в`, `на`, `с`, `и`, `а`, `но`, `по`, `к`, `о`, `у` — если строка заканчивается ими и следующая строка начинается не со строчной (обрыв), предлог удаляется; если со строчной — строки склеиваются.
- **Пробелы и пунктуация**: убрать пробел перед `.,;:!?`; добавить пробел после `.,;:!?` перед буквой (кроме чисел `3.5`, URL, доменов `hh.ru`, времени `12:30`); убрать пробел после слэша в `и/или`, `А/Б` и аналогичных (в заметке 145 мест) — но не ломать URL и пути.
- **Повторяющаяся пунктуация**: `...` оставить, `,,`, `..`, `!!` → одна; пустые скобки `()` удалить.
- **Пустые маркеры**: строки из одного `-`, `*`, `•`, `—`, `_`, `=` (≥ 3) — разделители OCR/PDF → удалить.

Известный риск, перенесённый из заметки: правило «продолжение строки по строчной букве» срабатывало на доменах (`hh.ru`, начинаются со строчной) и приклеивало текст не к той строке. **Любое правило, зависящее от регистра первой буквы, обязано исключать домены, URL, e-mail, имена файлов и числа**. Для таких правил обязателен пример в `check-cleanup.ts`.

**D. Речь (`speech.ts`)** — применяется ко всему тексту, потому что «для всего одна фильтрация» (отдельного режима «только для речи» нет); правила безопасны и для обычного текста, т. к. консервативны.

Словарь паразитов вынесен в конфиг (`speech-fillers.ts`) с тремя уровнями:

|Уровень|Правило|Слова/выражения (стартовый набор)|
|---|---|---|
|`always`|удалять везде|`эээ`, `эм`, `ммм`, `э-э`, `хм`, `гм`, `эх`, `ну-у`|
|`delimited`|удалять только если выделено запятыми, тире или стоит в начале предложения; иначе не трогать|`ну`, `как бы`, `типа`, `короче`, `в общем`, `в общем-то`, `так сказать`, `как говорится`, `значит`, `вот`, `блин`, `собственно`, `в принципе`, `по сути`, `скажем так`, `это самое`, `как его`, `слушай`, `понимаешь`|
|`off`|не удалять (смысл часто несущий)|`то есть`, `например`, `итак`, `кстати`, `вообще`, `просто`|

Пример: «ну, мы как бы сделали, типа, отчёт» → «мы сделали отчёт». Но «типа данных» и «ну и ладно» не трогаются. Пользователь сказал, что всё остальное — релевантная информация; значит список **консервативный** и расширяется только по его запросу. После удаления: поправить регистр первой буквы предложения, убрать оставшиеся «, ,» и пробелы перед запятыми.

### 8.4. LLM-вариант

- **По умолчанию выключен, в этой итерации не реализуется.** Причина: стоимость, недетерминированность, риск «улучшить» смысл.
- Расширяемость: в `core/cleanup/index.ts` оставить именованную точку расширения `optionalLlmPass` (по умолчанию `null`), включаемую флагом `CLEANUP_LLM=off|on`. Флаг `on` в этой итерации завершает работу с ошибкой «не реализовано».
- **[ОТКРЫТО]** Пользователь отказался, но пока думает. Если решит включить: LLM-проход обязан сопровождаться проверкой, что смысл не изменился (сравнение количества чисел, имён и ключевых терминов до/после; откат при расхождении). Агент ничего не решает сам.

## 9. Валидатор

`core/validate` — отдельный модуль. Читает текст, ничего не меняет, возвращает `{ ok: boolean, violations: Violation[] }`, где `Violation { criterion, count, samples[≤3], fixable }`.

### 9.1. Критерии «чисто»

База — список из заметки (0 тегов, 0 хвостовых пробелов, 0 `U+FFFD`, 0 висячих предлогов, 0 пробелов после слэша), расширенный под речь:

|#|Критерий|Условие прохождения|
|---|---|---|
|V1|HTML/разметочные теги|0 вхождений `<…>` и HTML-сущностей|
|V2|Хвостовые пробелы|0 строк, оканчивающихся пробелом/табом|
|V3|Ведущие отступы|0 строк с ведущими пробелами/табами|
|V4|Лишние пустые строки|0 мест, где подряд > 1 пустой строки|
|V5|Двойные пробелы|0 вхождений внутри строки|
|V6|Символ замены|0 `U+FFFD`|
|V7|Невидимые символы|0 zero-width/управляющих/BOM/NBSP|
|V8|Склейки кириллицы с латиницей|0 слов со смешением алфавитов вне исключений|
|V9|Висячие предлоги/союзы|0 строк, оканчивающихся предлогом при продолжении абзаца|
|V10|Пробел после слэша / перед пунктуацией|0 вхождений|
|V11|Слова-паразиты уровня `always`|0 вхождений|
|V12|Паразиты уровня `delimited`|0 вхождений в выделенной позиции|
|V13|Подряд повторённые слова|0 (с учётом исключений)|
|V14|Обрезки слов|0 фрагментов вида `сл-␠` без продолжения; 0 `ро-ро-ро`|
|V15|Номера страниц и мусорные разделители|0 строк-«номер страницы» и строк из одних символов-разделителей|
|V16|Не пусто|После очистки ≥ 1 слова (иначе материал бессодержателен)|
|V17|Доля кириллицы|Для русскоязычного материала доля кириллицы среди букв ≥ порога (по умолчанию 0.5); иначе предупреждение, а не провал|
|V18|Предохранитель|Удалено ≤ `MAX_REMOVED_RATIO` исходного; иначе предупреждение|

Критерии V17 и V18 — **предупреждения** (`severity: "warn"`), не блокируют `ok`, но попадают в отчёт. Остальные — `error`.

### 9.2. Автопочинка (`autofix.ts`)

1. `validate(text)`.
2. Если есть `error` и они `fixable`: применить **только** правила, соответствующие нарушенным критериям (таблица соответствия критерий → rule ids хранится в одном месте).
3. Повторить до 3 проходов или пока не станет `ok`.
4. Если после 3 проходов нарушения остались → результат **всё равно выдаётся** (ничего не стираем), но отчёт получает статус `⚠ не пройдена` и перечень оставшихся нарушений с примерами. Автопочинка, которая зациклилась или не сходится, — сигнал в отчёт, а не падение бота.

## 10. Расшифровка (Whisper)

### 10.1. Абстракция провайдера

```ts
interface TranscriptionProvider {
  name: "groq" | "openai" | "local";
  transcribe(input: { buffer: Buffer; filename: string; mime: string; language: "ru"; prompt?: string }):
    Promise<{ text: string; durationSec?: number; model: string }>;
}
```

- Groq и OpenAI имеют OpenAI-совместимый эндпоинт расшифровки: оба провайдера делаются через один клиент с разным `baseURL`/ключом/моделью.
- `local` — только заглушка с понятной ошибкой «не реализовано». Модели локально на сервере Railway не запускаем.
- **[ОТКРЫТО] Провайдер не выбран** (Groq `whisper-large-v3`, OpenAI `whisper-1`/`gpt-4o-transcribe` или локально на машине пользователя). По умолчанию в `.env.example`: `WHISPER_PROVIDER=groq`. Агент реализует `groq` и `openai`, переключение одной переменной. Пользователь решит позже.
- Параметры: `language=ru`, `temperature=0`, формат ответа — plain text (без таймкодов, они не нужны).
- Формат: `.ogg` (opus) и популярные аудио-форматы принимаются провайдерами напрямую. **ffmpeg не нужен** (файлы ≤ 20 МБ). Если провайдер отверг формат — понятная ошибка пользователю, без конвертации.

### 10.2. Подсказка (`prompts/whisper-prompt.ts`)

Whisper принимает `prompt` (~224 токена) — подсказка контекста, улучшает русский, пунктуацию и редкие слова. Собирается из:

- стилевого шаблона: короткий образцовый русский текст с правильной пунктуацией и заглавными буквами;
- словаря терминов, имён, названий компаний из `WHISPER_PROMPT_TERMS` (env, через запятую) или из файла `prompts/whisper-terms.txt`.

Пользователь сам наполняет словарь. Агент создаёт файл со стартовыми комментариями-примерами и проверяет, что общая длина подсказки обрезается до лимита.

### 10.3. Постобработка

Расшифровка идёт в тот же `runCleanup` (тот же пайплайн, раздел 8): паразиты, обрезки слов, повторы. Отдельных LLM-правок русского нет.

## 11. Отчёт

Формат — компактное сообщение в Telegram (русский), примерно:

```
📋 Отчёт по загрузке — 21.11.2026 02:15

Материалы: 4 (голос ×2, файл ×1, текст ×1)
Было → стало: 18 420 → 15 960 символов (−13,4 %)
Аудио: 2 записи, 17 мин 40 с. Whisper: groq / whisper-large-v3

Удалено/исправлено по категориям:
• Механика (теги, пробелы, пустые строки): 312
• Артефакты файлов (номера страниц, колонтитулы, переносы): 41
• Дефекты (склейки, обрезки слов, пунктуация): 87
• Речь (паразиты, заикание, повторы): 164

Валидация: ✅ пройдена (V1–V16) | ⚠ предупреждения: нет
Автопочинка: 1 проход

Состояние для нарезки на чанки: текст чистый, структуры/заголовков нет
(нарезка будет по другому паттерну — не входит в эту итерацию)
```

Состав отчёта:

1. Список материалов (тип, имя файла/длительность, символов по каждому).
2. Символов до/после, процент удалённого.
3. Счётчики по категориям правил (из `stats`), по желанию — топ-5 сработавших правил.
4. Метаданные аудио: суммарная длительность, провайдер, модель; стоимость расшифровки — **только если** провайдер вернул цену/её можно посчитать по тарифу из конфига (иначе строку не выводить).
5. Результат валидации: статус, нарушенные критерии с примерами (без утечки длинных кусков текста: ≤ 60 символов на пример), предупреждения.
6. Число проходов автопочинки.
7. Блок «Подготовка к чанкованию» — **заглушка**: сейчас выводит только строку о том, что текст чистый и нарезка не выполнялась. Пользователь сказал, что в будущем отчёт будет акцентирован на чанках; поэтому `report.ts` строится секциями (`ReportSection[]`), чтобы потом добавить секцию чанков, не переписывая остальное.
8. Если отчёт > 4096 символов — разбить по секциям на несколько сообщений.

Diff «до/после» и превью **не нужны**.

`config/env.ts` валидирует env через `zod` и падает при старте с понятным списком недостающих переменных. Создать `.env.example` со всеми ключами (значения-заглушки):

## 13. Запуск: dev и прод

### 13.1. Dev: long polling (на машине пользователя)

- `npm run dev:bot` → `tsx src/scripts/dev-polling.ts`: загружает env, **сначала удаляет webhook** (`deleteWebhook`, иначе polling не заработает), затем `bot.start()`.
- Использует те же `createBot()` и те же обработчики, что и webhook (единая точка сборки бота), чтобы поведение не расходилось.
- **Рекомендация пользователю:** завести отдельного dev-бота в BotFather с отдельным токеном. Один токен нельзя одновременно держать на polling (локально) и на webhook (Railway): они будут выбивать друг друга.
- Next.js в dev-режиме для бота не нужен (`next dev` отдельно, если понадобится).

### 13.2. Прод: webhook на Railway

Railway — это просто хостинг; веб-сервер отдельно писать не нужно: им служит сам Next.js (`next start` слушает `PORT` и `0.0.0.0`).

Шаги (в README/комментариях к скрипту):

1. Создать сервис на Railway из репозитория, задать env-переменные (раздел 12), `BOT_MODE=webhook`.
2. В настройках сервиса: Networking → Generate Domain → получить публичный URL; записать в `PUBLIC_BASE_URL`.
3. Webhook-маршрут `src/app/api/telegram/webhook/route.ts` (`POST`): проверяет заголовок `X-Telegram-Bot-Api-Secret-Token` (не совпал → 401), вызывает `webhookCallback(bot, "std/http")`, быстро возвращает 200.
4. Регистрация webhook: `npm run set-webhook` → `setWebhook` с `url=<PUBLIC_BASE_URL><WEBHOOK_PATH>`, `secret_token`, `allowed_updates=["message","callback_query"]`, `drop_pending_updates=true`. Скрипт выводит `getWebhookInfo`. Параметр `--delete` вызывает `deleteWebhook`. (Автоматическая регистрация на старте процесса допускается как опция `AUTO_SET_WEBHOOK=true`, но по умолчанию только ручной скрипт.)
5. Корректный URL Telegram API: `https://api.telegram.org/bot<TOKEN>/setWebhook?url=...` (в черновике заметки домен записан неверно).
6. Проверка здоровья: `GET /api/health` → `{ ok: true, mode }` для Railway (без секретов).

Дедупликация апдейтов по `update_id` (in-memory, окно последних N=200) защищает от повторной доставки Telegram.

## 14. Ошибки и сообщения пользователю

Все тексты в `bot/messages.ts`. Ошибки типизированы (`shared/errors.ts`: `UnsupportedFormatError`, `FileTooLargeError`, `AudioTooLongError`, `TranscriptionError`, `ParseError`, `EmptyContentError`, `SessionNotFoundError`, …).

|Ситуация|Сообщение пользователю (суть)|
|---|---|
|Не в whitelist|Молчание (без ответа)|
|Материал без `/StartProcess`|«Сначала вызови /StartProcess»|
|Неподдерживаемый формат|«Формат не поддерживается. Могу: pdf, md, txt, docx, голосовые и аудио»|
|Кружок/видео|«Кружки не обрабатываю, пришли голосовое или аудиофайл»|
|Файл > 20 МБ|«Файл слишком большой (N МБ, лимит 20)»|
|Аудио > 50 мин|«Запись длиннее 50 минут (N мин). Раздели её на две части и отправь снова» — материал не теряется и в чате не удаляется|
|PDF без текстового слоя|«В PDF нет текстового слоя, сканы не поддерживаются»|
|Whisper упал|«Не удалось расшифровать. Повторяю…» → после 3 попыток «Не получилось, отправь запись ещё раз»; сессия остаётся|
|Пустой результат|«В материале не нашлось текста»|
|Устаревшая кнопка|«Сессия устарела, начни заново /StartProcess»|
|Любая необработанная ошибка|«Что-то пошло не так, сессия сохранена, попробуй ещё раз» (в лог — тип и стек без содержимого текста)|

Ретраи: сеть Telegram и API Whisper — до 3 раз с нарастающей паузой; ошибки валидации/формата не ретраятся.

## 15. Этапы реализации

Каждый этап завершается проверкой критериев; следующий не начинается, пока предыдущий не принят.

**Этап 1. Каркас бота и `/StartProcess`**

- Создать `config/env.ts`, `bot/` (grammY), whitelist, команды `/start /help /StartProcess /done /cancel /status`.
- Webhook-маршрут, `dev-polling.ts`, `set-webhook.ts`, `/api/health`, `.env.example`.
- Сессия в памяти, очередь, дедупликация апдейтов, инлайн-кнопки (пока на заглушках).
- _Приёмка:_ в dev-режиме бот отвечает на команды; `/StartProcess` открывает сессию; на сообщение без команды отвечает подсказкой; запуск `next build` проходит; webhook-маршрут отклоняет запрос без секрета.

**Этап 2. Текст и файлы**

- Приём текста (склейка кусков), приём файлов pdf/md/txt/docx, caption, пересланные.
- `parser/*`, лимит 20 МБ, ошибки формата.
- После каждого материала — сообщение с кнопками «Ещё добавлю / Загрузить в систему».
- _Приёмка:_ 3 разных файла + текст подряд попадают в сессию в правильном порядке; `.doc`, `.html`, `.rtf`, изображение дают корректную ошибку; PDF-скан даёт ошибку про текстовый слой; `/status` показывает состав.

**Этап 3. Голос и аудио**

- Провайдер Whisper (groq + openai), подсказка с термином, проверка длительности до скачивания, ограничение 50 минут, кружки отклоняются.
- _Приёмка:_ голосовое и аудиофайл расшифровываются в русский текст; запись > 50 мин отклоняется с нужным сообщением и **не теряется**; смена `WHISPER_PROVIDER` работает без правок кода.

**Этап 4. Очистка и валидатор**

- `core/cleanup`, `core/validate`, `autofix`. Скрипт `scripts/check-cleanup.ts` с «грязным образцом» (теги `<br>`, `<u>`, номера страниц, колонтитулы, склейки `наCAC`, гомоглифы, `по-по-посмотрим`, «ну, как бы», `U+FFFD`, `hh.ru`, пробелы после слэша, висячие предлоги) и проверкой: после прогона `validate` даёт `ok`, счётчики совпадают с ожидаемыми.
- _Приёмка:_ `npm run check:cleanup` завершается кодом 0; повторный прогон даёт идентичный результат (идемпотентность: `clean(clean(x)) === clean(x)`); домены, URL, e-mail и числа не искажаются.

**Этап 5. Отчёт и выдача**

- `services/finalize`, `report`, `TelegramSink` (файл `.md` + отчёт), предохранитель, разбиение длинного отчёта.
- _Приёмка:_ полный сквозной сценарий `/StartProcess` → материалы → «Загрузить в систему» → файл `.md` и отчёт; ошибки раздела 14 воспроизводятся; в логах нет содержимого текстов; на диске после обработки нет временных файлов.

- Запись в БД, Prisma, любые репозитории.
- Веб-интерфейс, админка.
- OCR сканов, `.doc`, `.rtf`, `.html`, видео, кружки.
- LLM-очистка (только точка расширения, не реализация).
- Локальный Whisper (только заглушка провайдера).
- Подписчики, рассылки, несколько пользователей.
- Хранение сырого входа и результатов.
- Таймкоды, диаризация, ffmpeg-конвертация, разрезание длинного аудио автоматически.
- Тесты (кроме самопроверочного скрипта очистки).
- Автоматический деплой/CI.

## 17. Открытые вопросы (**[ОТКРЫТО]**, не решать за пользователя)

1. **Провайдер Whisper:** Groq, OpenAI или локально (на машине пользователя)? Нужны ключи и бюджет.
2. **LLM-очистка:** включать ли вообще (пользователь склоняется к «нет, дорого»); при «да» — какая модель и как проверять сохранность смысла.
3. **Список паразитов:** утвердить стартовый набор раздела 8.3-D на реальных записях; уровни `always`/`delimited`/`off` могут сдвигаться.
4. **Куда уходит результат дальше:** как именно «Загрузить в систему» отправляет данные в основную систему (API, очередь, БД?). Сейчас результат возвращается в чат файлом `.md` + отчёт.
5. **Формат объединённого результата:** сейчас элементы склеиваются через одну пустую строку. Нужны ли маркеры границ источников для будущего чанкера?
6. **Секция чанков в отчёте:** состав появится вместе с этапом нарезки.
7. **Прод-домен и деплой:** подтвердить, что аккаунт Railway и сервис созданы (в репозитории есть `.railwayignore`), и выбрать регион/домен.

## 18. Преимущества выбранного подхода

- ✅ Один код бота для dev (polling) и прода (webhook): поведение одинаково, меняется только способ доставки апдейтов.
- ✅ Ошибки видны сразу при приёме материала, а не при финализации; ничего не теряется (длинное аудио не стирается, а возвращается с понятным сообщением).
- ✅ Очистка воспроизводима и измерима: каждое правило считает срабатывания, отчёт показывает, что именно было убрано.
- ✅ Валидатор независим от очистки и не может «зачесть сам себя»; автопочинка работает точечно и ограничена тремя проходами.
- ✅ Консервативная очистка речи: удаляется только мусор, смысловые слова защищены уровнями словаря и предохранителем по доле удалённого.
- ✅ Провайдер Whisper и режим вывода меняются конфигом, поэтому открытые вопросы (Groq/OpenAI/локально, «только отчёт») не блокируют разработку.
- ✅ Бот ничего не хранит: нет БД, нет файлов, нет логов с содержимым.
