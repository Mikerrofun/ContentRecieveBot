# Очистка и валидация текста

## 1. Зачем

Транскрипты Whisper и загруженные документы содержат мусор: HTML-теги, номера
страниц, склеенные слова, слова-паразиты, заикания, обрывки фраз. Этот мусор
ухудшает качество чанков и RAG-поиска. Модуль очистки приводит текст к чистому
виду детерминированными правилами, а валидатор проверяет результат и при
необходимости запускает точечную автопочинку.

## 2. Где что лежит

```
src/shared/config/speech-fillers.ts   — словари паразитов, исключения, guard «ну»
src/shared/lib/text-patterns.ts       — общие паттерны (границы слов, предлоги)
src/shared/lib/protect.ts             — защита токенов (URL, e-mail, hh.ru, 12:30)
src/core/cleanup/
  rules.ts        — реестр правил, порядок применения, CleanupStats
  mechanical.ts   — категория «mechanical»
  file-artifacts.ts — категория «file-artifacts»
  defects.ts      — категория «defects»
  speech.ts       — категория «speech»
  index.ts        — runCleanup: все категории + финальная нормализация
src/core/validate/
  criteria.ts     — критерии «чисто» V1–V22 (независимая детекция)
  index.ts        — validate()
src/core/autofix.ts  — цикл validate → точечная починка → validate (макс. 3 прохода)
src/features/report/index.ts — секции отчёта бота
src/scripts/check-cleanup.ts      — smoke-тест очистки
src/scripts/check-cleanup-cases.ts — регресс-кейсы из ревью текста
```

## 3. Порядок применения правил

Категории применяются строго по порядку — каждая следующая видит уже
нормализованный текст:

1. **mechanical** — теги, невидимые символы, пробелы, пустые строки;
2. **file-artifacts** — номера страниц, колонтитулы, жёсткие переносы, дефисы;
3. **defects** — склейки, обрезки, ложные старты, заикание, повторы,
   многоточия, пунктуация;
4. **speech** — слова-паразиты, растянутые слова, пунктуация после вырезаний.

Внутри категории порядок задаёт массив в `rules.ts`. Финальная нормализация
пробелов (`m-normalize-final`) выполняется всегда последней.

## 4. Правила очистки

### Mechanical

| ID | Что делает |
|---|---|
| `m-strip` | обрезка пробелов по краям |
| `m-tags` / `m-html-tags` | удаление HTML/Markdown-тегов и HTML-сущностей |
| `m-blank-lines` | схлопывание 3+ пустых строк |
| `m-eol-bom` | BOM, CRLF → LF |
| `m-final-spaces` | пробелы в концах строк |
| `m-invisible` | zero-width, soft hyphen, управляющие символы |
| `m-replacement-char` | символы замены `�` |
| `m-whitespace` | табы → пробел, двойные пробелы |
| `m-normalize-final` | финальная нормализация |

### File-artifacts

| ID | Что делает |
|---|---|
| `f-page-numbers` | строки-номера страниц |
| `f-headers-footers` | повторяющиеся колонтитулы |
| `f-hard-wraps` | склейка жёстких переносов внутри абзаца (флаг `joinHardWraps`) |
| `f-dehyphenate` | «привет-» + перенос → «привет» |
| `f-toc-dots` | точки-заполнители оглавлений |

### Defects

| ID | Что делает |
|---|---|
| `d-homoglyphs` | латиница↔кириллица в одном слове |
| `d-glue` | «приветКак дела» → пробел между словами |
| `d-truncated` | обрывки «пробле-» |
| `d-false-start-dash` | «чёр— нет, ...» → вырезание до отмены |
| `d-false-start-comma` | «чёр, нет, ...» → вырезание до отмены |
| `d-false-start-fragment` | «чёр— » → вырезание обрывка |
| `d-stutter` | «по-подожди» → «подожди» |
| `d-repeated-words` | «в в», «да-да», «забыл, да, забыл» → одно слово |
| `d-ellipsis` | мусорные знаки в начале текста, «—,»/«…,» → один знак, многоточие внутри предложения → запятая, повтор слова после многоточия удаляется |
| `d-hanging-prepositions` | «на\nстоле» → «на столе» |
| `d-punct-space` | пробелы вокруг знаков препинания |
| `d-slash-space` | «и / или» → «и/или» |
| `d-repeated-punct` | «..», «,,», «?!?» → один знак |
| `d-empty-markers` | пустые маркеры списков |

### Speech

| ID | Что делает |
|---|---|
| `s-fillers-always` | паразиты-заполнители везде: эээ, ммм, вот, ага… |
| `s-fillers-delimited` | паразиты в выделенной позиции: типа, короче, в общем, наверное, походу, в смысле, честное слово…; «да»-тег в конце фразы и между запятыми |
| `s-elongated` | «нууу», «да-а-а» → «ну», «да» |
| `s-punct-fix` | хвосты после вырезаний, регистр предложений, «И, ...» → «И ...» |

### Ключевые приёмы

- **Границы слов** (`WORD_LEFT_BOUND`/`WORD_RIGHT_BOUND`) — филлер не
  вырезается из середины слова.
- **Защита токенов** (`isProtectedToken`) — URL, e-mail, домены, время и
  числа не трогаются ни одним правилом.
- **Умная запятая** (`fillerReplacement` в `speech.ts`): если филлер потребил
  запятую после себя, она возвращается предыдущему слову
  («забыл ну просто, наверное» → «забыл, наверное»), кроме случая, когда
  перед филлером стоит союз («И вот, иду я» → «И иду я»).
- **Guard «ну»** (`NU_CONJUNCTION_GUARD`): «ну и ладно», «ну а что» не
  трогаются.
- **Исключения повторов** (`REPEATED_WORD_EXCEPTIONS`): «чуть-чуть»,
  «еле-еле», «едва-едва» и т.п. — легитимные удвоения.
- **Многоточие внутри предложения** (`d-ellipsis`): «...» между словами на
  одной строке → запятая, следующее слово приводится к нижнему регистру; если
  это слово уже звучало в последних трёх словах — оно удаляется
  («и сразу... Сразу понял» → «и сразу, понял»).

## 5. Критерии валидатора (V1–V22)

Критерии детектируют нарушения независимо от правил (свои regex'ы, те же
словари-конфиги). `severity: error` блокирует выдачу до автопочинки,
`warn` — только предупреждение.

| ID | Проверяет | Fixable | Правила автопочинки |
|---|---|---|---|
| V1 | HTML-теги, сущности | да | m-html-tags |
| V2 | пробелы в концах строк | да | m-whitespace |
| V3 | пробелы в началах строк | да | m-whitespace |
| V4 | 3+ пустых строк | да | m-blank-lines |
| V5 | двойные пробелы | да | m-whitespace |
| V6 | символы замены `�` | да | m-replacement-char |
| V7 | невидимые символы | да | m-invisible |
| V8 | гомоглифы/склейки | да | d-homoglyphs, d-glue |
| V9 | висячие предлоги | да | d-hanging-prepositions |
| V10 | пробелы вокруг пунктуации и слэша | да | d-punct-space, d-slash-space |
| V11 | паразиты-заполнители | да | s-fillers-always |
| V12 | паразиты в выделенной позиции, «да»-теги | да | s-fillers-delimited |
| V13 | повторы слов (в т.ч. «да-да») | да | d-repeated-words |
| V14 | обрывки, заикание | да | d-truncated, d-stutter |
| V15 | номера страниц, пустые маркеры | да | f-page-numbers, d-empty-markers |
| V16 | текст без слов | нет | — |
| V17 | доля кириллицы < 50% | warn | — |
| V18 | удалено > maxRemovedRatio | warn | — |
| V19 | ложные старты | да | d-false-start-* |
| V20 | растянутые слова | да | s-elongated |
| V22 | мусорные знаки: «...,», «—,», многоточия внутри предложений | да | d-ellipsis |

## 6. Поток данных

```
вход (транскрипт/документ)
  → parse (pdf/docx/text)
  → runCleanup (4 категории правил, stats по каждому правилу)
  → autofix: validate → точечная починка нарушенных error-критериев → validate
       (макс. 3 прохода; после — результат всё равно выдаётся,
        оставшиеся нарушения попадают в отчёт, бот не падает)
  → buildReport/renderReport (секции ≤ 4096 символов)
  → чанкование (вне этой итерации)
```

`CleanupStats` считает срабатывания по каждому правилу — из них собирается
секция «Что исправлено» отчёта.

## 7. Почему так

- **Детерминированность.** Одинаковый вход → одинаковый выход; идемпотентность
  проверяется smoke-тестом (`clean(clean(x)) === clean(x)`).
- **Консервативность.** Смысловые слова («то есть», «например», «кстати»,
  «просто») не удаляются; позиционные паразиты — только в выделенной позиции.
- **Единый источник конфига.** Словари живут в `speech-fillers.ts`, правила и
  критерии импортируют их оттуда — списки не разъезжаются.
- **Независимая детекция.** Критерии валидатора написаны своими regex'ами,
  чтобы автопочинка не «самоподтверждалась».

## 8. Как добавить правило

1. Описать правило в соответствующем файле категории (`run` возвращает
   `{ text, count }`).
2. Зарегистрировать в массиве категории в `rules.ts` (порядок важен).
3. Добавить человекочитаемую метку в `RULE_LABELS` (`features/report/index.ts`).
4. Если правило чинит новое нарушение — добавить критерий в `criteria.ts`
   (детекция независимо от правила) и маппинг `Vxx: ["rule-id"]` в
   `CRITERION_RULES` (`core/autofix.ts`).
5. Добавить кейс в `src/scripts/check-cleanup-cases.ts`, прогнать
   `npx tsx src/scripts/check-cleanup.ts` и `npx tsc --noEmit`.

## 9. Ограничения

- **Смысловые повторы (тавтология)** — «бегут, спешат, торопятся»,
  «подумать, поразмышлять», «примерно на тысячу символов… именно на 1000
  знаков» — детерминированными правилами не убираются: требуется понимание
  синонимии. Это задача LLM-прохода (флаг `CLEANUP_LLM`), вынесенного за
  рамки текущей итерации.
- **Многоточие → запятая** понижает регистр следующего слова; имя
  собственное после многоточия в середине строки может быть ошибочно
  приведено к нижнему регистру (в транскриптах речи риск минимален).
- **«ну просто»** удаляется везде как цельная фраза; конструкция
  «сказал ну просто так» превратится в «сказал так».
